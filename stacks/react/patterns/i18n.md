# Pattern — i18n

**Read when:** writing any user-facing string, rendering an API error, formatting a date,
number or currency, or adding a locale.

`react-i18next` on `i18next`. Chosen over Lingui because it needs no extraction/compile step
in the build, its plural and interpolation rules come from ICU-compatible `i18next` JSON, and
MSW/Vitest need nothing extra to load it.

---

## Files

```
src/lib/i18n.ts                   init: resources, fallback 'en', interpolation escaping off (React escapes)
src/locales/<lang>/<ns>.json      one namespace per feature + common + errors
```

`en` is the source. Keys are **semantic**, never the English sentence:
`application.submit.blocked`, not `"Submit is blocked until…"`. A key names what the string
is *for*, so a copy change is not a key change in every locale file.

Namespaces: `common` (buttons, nav, empty states), `errors` (API codes), one per feature.
A component uses `useTranslation('<feature>')` and reaches `common:` by prefix.

## No user-facing literal in a component

Every string the user can see or hear goes through `t()`: text, `aria-label`, `placeholder`,
`title`, `alt`, toast copy, validation messages. Lint enforces it —
`i18next/no-literal-string` (or the project's equivalent) is in the lint gate, so a literal
fails `npm run lint`.

Zod messages: `z.string().min(1, { message: 'validation.required' })` and the `FormField`
translates the key. The schema never holds prose.

## API errors render by code

```ts
t(`errors.${error.code}`, { defaultValue: t('errors.UNKNOWN') })
```

The backend's error-code table and the `errors` namespace are **the same list**. A code
without a translation is a review-blocking finding on either side; the fallback exists so a
missing one degrades to a generic message rather than a key on screen, not so it can be
left missing.

Branch on `error.code` for behaviour, never on status — [data](data.md).

## Plurals and interpolation

```json
"documents.remaining_one": "{{count}} document remaining",
"documents.remaining_other": "{{count}} documents remaining"
```

`t('documents.remaining', { count })`. Never concatenate strings or pick a form with a
ternary — word order and plural categories differ per language.

## Dates, numbers, currency

Through `Intl.*` with the active locale, wrapped once in `lib/format.ts`:

```ts
formatDate(value, { dateStyle: 'medium' })       // Intl.DateTimeFormat(locale, …)
formatCurrency(amount, currency)                  // Intl.NumberFormat(locale, { style: 'currency', currency })
```

No hand formatting, no `toLocaleDateString` scattered through components. Tests pin `TZ`
and assert the string as a reader in that locale sees it.

## Locale state

Lives in the theme store beside `theme` — persisted, applied before paint, `lang` set on
`<html>`. Changing it calls `i18n.changeLanguage` and nothing else re-renders on its own
behalf. Server-driven copy (a notification's stored title) is rendered as-is; it was
written in the language it was written in.

RTL: `dir` follows the locale on `<html>` and layout uses logical properties (`ms-`, `pe-`,
`start`/`end`) so a mirrored locale is a token change, not a rewrite. Not exercised yet;
noted so nothing is built that forecloses it.

## Tests

Render through the shared helper with `en` loaded. Assert on translated text, not keys — a
key on screen is itself the bug. A test that adds a string adds it to `en` in the same
change.
